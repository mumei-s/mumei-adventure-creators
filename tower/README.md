# Atelier Tower

無名S noteの参加型マンション。サイトは既存のGitHub Pagesの `/tower/` で公開されます。星灯りの街と相互に移動できます。

- 12階×12室。IDと住人キャラ画像を読み込むと、記事のテーマと画像の配色から内装・家具・窓を組み立てます。下見で動かしてから入居できます。
- 既存の住人は鍵で入室し、改装画面からキャラを設定できます。トップで同じIDと画像を入れると、部屋の作り直しも下見できます。
- 断面ビューで住人の部屋を訪ねられます。床のタップ、画面の方向ボタン、矢印キーで歩けます。レイアウトに応じて住人の動きと家具の当たり判定を計算します。
- エレベーターで階を移動し、ロビーの「今日の出来事」から実際に公開されている部屋やnote作品を訪ねられます。
- noteの自己紹介に一時コードを入れて公開します。確認用コードとブラウザの鍵は別々に発行します。本人確認済みの鍵でのみ改装、ゲスト先への訪問スタンプ、退去ができます。
- 鍵を再発行すると旧鍵が失効します。退去は部屋・画像・スタンプを削除し、空室を戻します。
- 公開記事の一覧は入居、鍵の再発行、改装時の明示的な更新で取得します。
- 14Fはオーナー専用室です。13F天空ラウンジ、1Fエントランスと管理人室、車寄せ・立体駐車場・駐輪コート・バイク置き場、B1地下駐車場、B2設備室、B3免震見学回廊には断面ビューからも入れます。
- 共用部は登録済みのキャラを引き継ぎます。歩く視点と全景を切り替え、各施設のイラスト２枚・専用サムネイル・note記事へ進めます。ラウンジの他の住人は公開登録アバターの展示で、リアルタイムの接続人数ではありません。
- 車両は地下・立体駐車場・自転車・バイクの４区画に独立して登録できます。号室から区画番号を決め、部屋の鍵と更新バージョンで保存します。1Fの管理人室で管理人、B2の設備室で技術部の役割を選べます。改装後も車両と参加状態を保持します。
- 防犯モニターと設備の計器はゲーム内の演出です。実際の映像や設備には接続しません。

## 運用

Pagesの公開対象はルートの `scripts/stage-pages.mjs` で管理します。`tower/supabase/` は公開サイトに含まれません。既存のAtelierのSupabaseプロジェクトで `supabase/migrations/` のマイグレーションを適用し、`creator-tower` Edge Functionを `verify_jwt = false` でデプロイします。公開閲覧以外のアクセスはEdge Functionが目的別に判定し、データベースではROOM IDと鍵のハッシュを検証します。サービス用の鍵にはEdge Functionの環境変数を使用します。

ローカルで画面を見るには、リポジトリのルートで `python3 -m http.server 8000` を実行し、`http://localhost:8000/tower/` を開きます。APIは本番につながります。

公開プロフィールと本棚の取得にはnoteの公開エンドポイントを使用しています。仕様が変わった場合はEdge Functionの `publicAccount` と `profileWithArticles` を確認してください。

`supabase/facility-rpc.sql` は既に本番へ反映された共用施設クエリの保存用スナップショットです。管理人も施設名簿に表示します。新規環境を用意する場合は既存マイグレーションの後にこのクエリを適用します。Edge Functionのソースは本番version 6と同期しています。

検査：`npm --prefix halloween ci` の後、`node --test tower/tests/*.test.mjs scripts/stage-pages.test.mjs`。車両所有権、更新競合、４区画の独立保存、改装時の保持、公開応答からの画像データ除外を検査します。

ブラウザ検査：ルートを4173番で配信し、Playwrightが使える環境で `node tower/tests/browser-flow.cjs`。必要に応じ `BROWSER_EXECUTABLE` を指定します。４画面サイズで11施設、歩行、車両添付、記事導線、乗車を確認し、画像は一時ディレクトリへ保存します。登録APIをテスト用応答へ置き換えるため、本番の部屋や車両は書き換えません。

`node tower/tests/pwa-browser-flow.cjs` はChromeのPWAマニフェスト解析、起動URL、実際の入退館ドアの表示、街との往復と戻る操作を検査します。
